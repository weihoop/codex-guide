# 模型与推理强度选择指南

本文整理 Codex 在服务器运维、部署发布、云资源创建、编码和故障排查等高影响场景下的模型选择建议。

> 说明：不同产品界面里可能把同一模型的推理强度标成 `low`、`medium`、`high` 等。这里的建议聚焦使用策略；具体可用模型、价格和命名以 OpenAI 官方文档和当前账号界面为准。

## 一句话建议

如果 Codex 会读取代码、执行命令、操作服务器、修改基础设施或影响生产环境，默认选择 `medium`。`low` 适合简单、低风险、容易验证和回滚的辅助任务。

```text
日常问答 / 简单改文案 / 小脚本       -> low
常规编码 / 部署 / 排障 / 云资源操作  -> medium
生产事故 / 复杂迁移 / 安全权限变更   -> medium 或更高 + 人工确认
```

## `low` 和 `medium` 的区别

`low` 和 `medium` 通常不是两个完全不同的模型，而是同一模型在不同推理强度下的运行方式。

| 维度 | low | medium |
| --- | --- | --- |
| 推理深度 | 较浅 | 更充分 |
| 响应速度 | 更快 | 稍慢 |
| 成本 | 通常更低 | 通常更高 |
| 适合任务 | 简单问答、摘要、命令解释、小脚本 | 编码、排障、部署、云资源和多步骤分析 |
| 主要风险 | 容易漏掉边界条件和隐藏风险 | 更稳，但仍需要验证和权限控制 |

## 按场景推荐

| 场景 | 推荐设置 | 原因 |
| --- | --- | --- |
| 操作服务器、SSH 排障 | `medium` 起步 | 需要串联日志、进程、网络、磁盘、权限和时间线 |
| 部署 / 发布 | `medium` | 需要先检查状态、执行变更、验证结果和准备回滚 |
| 创建 AWS / 云资源 | `medium`，复杂架构用更高档 | IAM、网络、账单和安全组配置都可能产生长期影响 |
| Terraform / Kubernetes / Docker 排障 | `medium` 或更高 | 状态、依赖和运行时环境复杂，低推理容易只看表象 |
| 常规编码、改 bug、重构 | `medium` | 需要理解上下文、维护测试和避免回归 |
| 简单脚本、日志摘要、命令解释 | `low` 可以 | 影响范围小，结果容易人工检查 |
| 生产事故、数据迁移、权限/IAM/网络安全 | 不建议 `low` | 错误成本高，必须更重视计划、验证和回滚 |

## `5.4` 和 `5.5` 怎么选

如果界面同时提供 `5.4` 和 `5.5`，可以按“新模型优先、稳定任务保守”的原则选择。

| 维度 | 5.4 | 5.5 |
| --- | --- | --- |
| 默认定位 | 更偏稳定、熟悉、可预测 | 更偏新能力、更强推理和更好工具使用 |
| 适合场景 | 已验证的固定工作流、批量任务、成本敏感任务 | 新项目、复杂排障、架构设计、跨系统操作 |
| 风险 | 能力上限可能低一些 | 新模型在少数边缘场景可能需要重新校准提示词 |
| 推荐用法 | 作为稳定基线或回退模型 | 作为默认主力模型，尤其配 `medium` |

实用选择：

- 服务器运维、部署发布、AWS 资源创建：优先 `5.5 medium`。
- 生产事故、权限/IAM、复杂网络问题：`5.5 medium` 起步，必要时升更高推理强度，并强制人工确认关键命令。
- 已经跑顺的自动化脚本、固定格式批处理：可以继续用 `5.4 medium` 或 `5.4 low`，以稳定和成本为先。
- 简单说明、日志摘要、命令解释：`5.5 low` 或 `5.4 low` 都可以。
- 如果 `5.5` 在某个项目上表现不稳定：临时回退 `5.4 medium`，并记录差异，避免在生产窗口临场调参。

## 高影响操作的推荐工作流

让 Codex 直接操作服务器或云资源时，建议把提示词写成“先计划、再执行、逐步确认”。

```text
请先只诊断，不做修改：
1. 说明你要检查哪些信息
2. 列出可能原因和风险
3. 给出执行计划、回滚方案和验证方式
4. 等我确认后再执行有副作用的命令
```

执行阶段建议：

```text
按步骤执行，每一步完成后都输出：
- 执行了什么
- 关键输出是什么
- 是否符合预期
- 下一步是否安全
```

## 安全边界

- 对生产环境使用 `medium` 不能替代人工确认、最小权限和备份。
- 涉及删除、覆盖、迁移、扩容、开放公网访问、修改 IAM 或安全组时，要求 Codex 先说明影响范围和回滚方式。
- Terraform、Kubernetes、数据库迁移等任务应先运行只读检查或 dry-run，例如 `terraform plan`、`kubectl diff`、迁移预检查。
- 不要把长期凭证、私钥、数据库密码直接贴进对话；优先使用本机环境变量、临时凭证或只读角色。

## 推荐默认配置

```text
默认主力：5.5 medium
低风险辅助：5.5 low
稳定回退：5.4 medium
批量低成本：5.4 low 或 5.5 low
高风险生产：5.5 medium 或更高 + 明确审批 + 回滚方案
```

最稳妥的组合不是“模型越强越好”，而是：合适模型 + 合适推理强度 + 沙箱/审批 + 可验证的操作流程。
